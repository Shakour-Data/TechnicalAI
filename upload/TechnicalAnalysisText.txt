## ۱. مقدمه و بیان مسئله

### ۱-۱. چالش‌های بازارگردانی در ایران

بازارگردانی در ایران با چالش‌های ساختاری متعددی مواجه است که بدون ابزار ساختارمند، منجر به **هزینه‌های میلیاردی، ریسک عملیاتی و توقف فعالیت** می‌شود:

| چالش | شرح |
|------|------|
| **مدیریت دسترسی پیچیده** | بدون سیستم RBAC ساختارمند، کنترل دسترسی کاربران دشوار است |
| **پراکندگی سیستم‌ها** | ابزارهای مختلف بدون یکپارچگی، مدیریت سامانه را پیچیده می‌کند |
| **فقدان نظارت متمرکز** | بدون داشبورد مدیریتی، نظارت بر عملکرد سیستم ناممکن است |
| **تشدید الزامات نظارتی** | سازمان بورس الزامات را تشدید کرده و جریمه‌های تخلفاتی افزایش یافته‌اند؛ پایش دستی دیگر پاسخگو نیست |
| **ریسک عدم دسترسی** | بازار ۲۴ ساعته و پرنوسان است، اما در ساعات تعطیلی بازار سرمایه امکان واکنش به اخبار جهانی وجود ندارد |
| **چالش‌های زیرساختی** | نبود استانداردهای فنی واحد، سامانه‌های KYC ناکافی و فقدان ریال دیجیتال برای تسویه |

### ۱-۲. چالش‌های خاص بازارگردانی توکن‌ها در مزدکس

علاوه بر چالش‌های عمومی بازارگردانی در ایران، بازارگردانی توکن‌های بهادار در پلتفرم مزدکس با چالش‌های منحصربه‌فردی مواجه است که ناشی از ماهیت **بازار توکنیزه‌شده** و **زیرساخت بلاکچین** است:

#### ۱-۲-۱. قفل بودن توکن‌ها در پلتفرم و محدودیت نقدشوندگی

بزرگ‌ترین چالش بازارگردانی توکن در مزدکس این است که **توکن‌های لیست‌شده غیرقابل‌برداشت‌اند و در پلتفرم قفل می‌مانند**؛ خروج از دارایی فقط با فروش آن در داخل مزدکس ممکن است. این محدودیت، بازارگردان را از امکان انتقال دارایی به بازارهای دیگر برای آربیتراژ یا مدیریت موجودی محروم می‌کند و عمق بازار را به‌شدت کاهش می‌دهد.

#### ۱-۲-۲. نقدشوندگی بسیار کم و عمق ناکافی بازار

نقدشوندگی در اکثر توکن‌های مزدکس بسیار کم است و تنها بخشی از توکن‌ها عمق کافی دارند. این وضعیت باعث می‌شود:
- فروش سریع حجم بزرگ با **اسلیپیج قابل‌توجه** همراه شود
- بازارگردان نتواند به‌راحتی پوزیشن خود را مدیریت کند
- اختلاف قیمت بین مزدکس و بازار پایه (بورس کالا) به‌صورت ساختاری باقی بماند

#### ۱-۲-۳. وابستگی به مجوز سندباکس و ریسک رگولاتوری

مدل کسب‌وکار مزدکس به **مجوز سندباکس کوتاه‌مدت سازمان بورس** وابسته است؛ در صورت عدم تمدید، مدل توکن بهادار متوقف می‌شود. این ریسک ساختاری، برنامه‌ریزی بلندمدت بازارگردان را با ابهام مواجه می‌کند.

#### ۱-۲-۴. ریسک قطعی زیرساخت و اختلالات شبکه

تجربیات اخیر نشان می‌دهد که در بحران‌های سیاسی و قطعی اینترنت، زیرساخت‌های رمزارزی ایران با اختلال شدید مواجه می‌شوند:
- کاهش ۹۹٪ اتصال اینترنت در بحران‌های اخیر
- بازارسازها اتصال API خود را از دست می‌دهند و سیستم‌های معاملاتی خودکار قطع می‌شوند
- صرافی‌ها به حالت محدودسازی ریسک (Risk Containment) می‌روند و برداشت‌ها را با تأخیر انجام می‌دهند

#### ۱-۲-۵. عدم امکان آربیتراژ سنتی و مسئولیت کامل بازارگردان

به دلیل **قفل بودن توکن‌ها در پلتفرم**، استراتژی‌های آربیتراژ سنتی (خرید در یک بازار و فروش در بازار دیگر) قابل اجرا نیستند. بازارگردان مسئولیت کامل تعادل قیمت را بر عهده دارد و باید از طریق مدیریت موجودی و نقدینگی داخلی، قیمت را به NAV نزدیک نگه دارد.

#### ۱-۲-۶. دوگانگی نقش بازارساز (Market Maker)

در صرافی‌های داخلی، بازارساز می‌تواند هم **نقدشوندگی ایجاد کند** و هم به ابزاری برای **واش‌تریدینگ و دستکاری قیمتی** بدل شود. این دوگانگی، نظارت بر عملکرد بازارگردان را ضروری می‌سازد و نیاز به سیستم‌های پایش خودکار و شفاف را دوچندان می‌کند.

#### ۱-۲-۷. چالش‌های حقوقی و قراردادی توکنیزاسیون

عدم وجود چارچوب حقوقی مشخص برای قراردادهای هوشمند و توکن‌های بهادار، ریسک حقوقی برای بازارگردان ایجاد می‌کند. تعدد نهادهای تنظیم‌گر (بانک مرکزی، سازمان بورس، وزارت ارتباطات) و تعارض صلاحیت‌ها، محیطی می‌سازد که تبعیت از مقررات یک نهاد لزوماً از تخلف در چشم نهاد دیگر مصون نمی‌دارد.

### ۱-۳. راه‌حل پیشنهادی

سامانه **«تصمیم‌یار بازارگردان»** با رویکردی **شفافیت، مستندسازی و اتوماسیون**، به‌عنوان یک اکوسیستم یکپارچه عمل می‌کند:

- **ساختارمند**: تصمیمات بر مبنای ۱۲ عامل کلیدی و ماتریس ۴×۴ (بر اساس نظرات خبرگان)
- **یکپارچه**: اتصال مستقیم به BRS API بورس و پایش خودکار تعهدات
- **مستند**: تمام تصمیمات با قابلیت ردیابی و گزارش‌گیری
- **انطباق‌پذیر**: طراحی‌شده برای شرایط خاص بازار توکنیزه مزدکس (قفل بودن توکن، نقدشوندگی کم، ریسک رگولاتوری)

import requests
from bs4 import BeautifulSoup

def get_gold_price():
    url = "https://www.tgju.org/profile/gold-18k"
    headers = {"User-Agent": "Mozilla/5.0"}
    response = requests.get(url, headers=headers)
    soup = BeautifulSoup(response.text, "html.parser")
    # استخراج قیمت از جدول
    price = soup.find("span", {"class": "value"}).text
    return price

## ۴. موتور پیش‌بینی (Prediction Engine)

### ۴-۱. مدل تخمین NAV لحظه‌ای (برای زمان بسته بودن بازار)

**فرمول بنیادین:**

```
NAV_Estimated = NAV_Last × [(XAU_Current / XAU_At_Last_NAV)^α × (USDT_Current / USDT_At_Last_NAV)^β × Premium_Factor]
```

**ضرایب پیشنهادی (به‌روزرسانی هفتگی با مدل رگرسیون):**
- **α (وزن انس طلا)**: ۰.۳۵
- **β (وزن تتر/دلار)**: ۰.۶۵

**Premium_Factor** بر اساس حباب سکه در بازار آزاد:

```
Gold_Intrinsic_Value = XAU/USD × USDT/IRR × 0.0933 × 1.05
Gold_Premium = (Seke_Price - Gold_Intrinsic_Value) / Gold_Intrinsic_Value
Premium_Factor = 1 + (Gold_Premium × 0.3)
```

**دامنه اطمینان مدل:**

| شرایط | خطای پیش‌بینی |
|-------|---------------|
| نوسان طلا < ۰.۵٪ در ۴ ساعت | < ۰.۳٪ |
| نوسان طلا ۰.۵-۱.۵٪ در ۴ ساعت | < ۰.۷٪ |
| نوسان طلا > ۱.۵٪ در ۴ ساعت | < ۱.۲٪ |

**به‌روزرسانی ضرایب α و β (شبه‌کد):**

```
Function Update_Alpha_Beta(Historical_Data):
    // 1. جمع‌آوری داده‌های ۳ ماه اخیر
    Data = Get_Last_3_Months(Historical_Data)
    
    // 2. اجرای رگرسیون خطی چندمتغیره
    Regression = LinearRegression(Data)
    
    // 3. به‌روزرسانی ضرایب با محدودیت
    α_New = Clamp(Regression.α, 0.20, 0.50)
    β_New = Clamp(Regression.β, 0.50, 0.80)
    
    // 4. نرمال‌سازی (جمع ضرایب = 1)
    Total = α_New + β_New
    α_Final = α_New / Total
    β_Final = β_New / Total
    
    Return α_Final, β_Final
```

### ۴-۲. مدل پیش‌بینی قیمت بازار

**الگوریتم:** XGBoost یا Random Forest با ویژگی‌های زیر:

| ویژگی | توضیح |
|-------|-------|
| NAV_Estimated | ارزش تخمینی هر واحد |
| XAU_Current | قیمت لحظه‌ای انس طلا |
| USDT_Current | قیمت لحظه‌ای تتر |
| Volume_MA_20 | میانگین متحرک حجم معاملات |
| RSI_14 | شاخص قدرت نسبی |
| BB_Upper/Lower | موقعیت قیمت نسبت به نوار بولینگر |
| Time_of_Day | ساعت معاملاتی |
| Day_of_Week | روز هفته |

**خروجی مدل:** `Price_Market_Predicted` و `Confidence_Score`

**فرمول محاسبه Confidence Score:**

\[
\text{Confidence\_Score} = \max\left(0, 1 - \frac{\text{RMSE}_{\text{model}}}{\text{RMSE}_{\text{baseline}}}\right)
\]

که در آن:
- `RMSE_model` = خطای ریشه میانگین مربعات مدل در ۳۰ روز اخیر
- `RMSE_baseline` = خطای مدل ساده (میانگین متحرک ۵ روزه)

**معیارهای ارزیابی مدل:**

| معیار | هدف | آستانه قابل قبول |
|-------|-----|------------------|
| **MAPE** | تخمین NAV | < ۱٪ |
| **RMSE** | پیش‌بینی قیمت | < ۰.۵٪ قیمت |
| **R²** | قدرت توضیح‌دهندگی | > ۰.۹ |
| **Hit Rate** | پیش‌بینی جهت حرکت | > ۶۰٪ |

**استراتژی آموزش و جلوگیری از Overfitting:**

| روش | توضیح |
|-----|-------|
| **Walk-Forward Validation** | آموزش بر روی داده‌های گذشته و آزمون بر روی داده‌های آینده |
| **Rolling Window** | پنجره زمانی متحرک (۶ ماه آموزش + ۱ ماه آزمون) |
| **Early Stopping** | توقف آموزش در صورت عدم بهبود خطای اعتبارسنجی |
| **Regularization** | استفاده از L1/L2 Regularization |

**مدیریت داده‌های پرت (Outliers):**
- **Winsorization**: محدود کردن داده‌های پرت به صدک‌های ۱٪ و ۹۹٪
- **Robust Scaling**: استفاده از Median و IQR
- **Filtering**: حذف روزهایی که نوسان > ۵٪ دارند

### ۴-۳. مدل پیش‌بینی حباب (Premium Prediction)

- اگر حباب > ۱.۰٪: سیگنال فروش (گران)
- اگر حباب < -۱.۰٪: سیگنال خرید (ارزان)
- بازه هدف: **۱± ۰.۵٪**

### ۴-۴. اندیکاتورهای تکنیکال (فرمول‌های کامل)

#### ATR (Average True Range)

\[
TR_t = \max(H_t - L_t, |H_t - C_{t-1}|, |L_t - C_{t-1}|)
\]

\[
ATR_t = \frac{ATR_{t-1} \times (n-1) + TR_t}{n}
\]

که در آن \(n = 14\).

#### RSI (Relative Strength Index)

\[
RSI = 100 - \frac{100}{1 + RS}
\]

\[
RS = \frac{\text{میانگین سود ۱۴ روز اخیر}}{\text{میانگین ضرر ۱۴ روز اخیر}}
\]

#### نوار بولینگر (Bollinger Bands)

\[
\text{BB\_Middle} = \text{SMA}(20)
\]

\[
\text{BB\_Upper} = \text{SMA}(20) + 2 \times \text{StdDev}(20)
\]

\[
\text{BB\_Lower} = \text{SMA}(20) - 2 \times \text{StdDev}(20)
\]

### ۵-۲. تعیین وزن‌ها بر اساس وضعیت بازار و اعتماد مدل

| وضعیت | Reference_Price | w₁ | ML_Price (w₂) | Technical_Price (w₃) |
|-------|-----------------|----|---------------|----------------------|
| **بازار باز (۱۲-۱۸)** | NAV اعلامی + تعدیل حباب | ۰.۶۰ | ۰.۲۵ | ۰.۱۵ |
| **بازار بسته (۱۸-۱۲) - خطای ML کم** | NAV_Last | ۰.۱۰ | ۰.۶۰ | ۰.۳۰ |
| **بازار بسته - خطای ML بالا** | NAV_Last | ۰.۱۰ | ۰.۳۰ | ۰.۶۰ |

### ۵-۳. شبه‌کد محاسبه قیمت پایه

```
Function Calculate_Base_Price(NAV, ML_Price, Tech_Price, Market_State, Confidence_Scores):
    if Market_State == "OPEN":
        w1, w2, w3 = 0.60, 0.25, 0.15
    else:
        if Confidence_Scores['ML'] > 0.85:
            w1, w2, w3 = 0.10, 0.60, 0.30
        else:
            w1, w2, w3 = 0.10, 0.30, 0.60
    
    Reference_Price = NAV
    Base_Price = (w1 * Reference_Price) + (w2 * ML_Price) + (w3 * Tech_Price)
    Return Base_Price
```

### ۵-۴. به‌روزرسانی وزن‌های ۱۲ عاملی (شبه‌کد)

```
Function Update_Weights_12Factors(Performance_Data):
    // 1. محاسبه دقت هر عامل در پیش‌بینی حرکت قیمت
    Accuracy = {}
    for each Factor in 12_Factors:
        Accuracy[Factor] = Calculate_Accuracy(Factor, Performance_Data)
    
    // 2. نرمال‌سازی وزن‌ها بر اساس دقت
    Total_Accuracy = Sum(Accuracy.values)
    Weights = {Factor: Accuracy[Factor] / Total_Accuracy for Factor in 12_Factors}
    
    // 3. اعمال محدودیت (حداقل و حداکثر وزن)
    for Factor in 12_Factors:
        Weights[Factor] = Clamp(Weights[Factor], 0.01, 0.25)
    
    // 4. نرمال‌سازی مجدد
    Total_Weights = Sum(Weights.values)
    Weights = {Factor: Weights[Factor] / Total_Weights for Factor in 12_Factors}
    
    Return Weights
```

## ۱۶. ماژول اجرای سفارشات: خرد کردن و سفارشات پله‌ای

### ۱۶-۱. تعریف و ضرورت

در بازارگردانی، حجم سفارش‌های بزرگ می‌تواند اثر بازار (Market Impact) ایجاد کند، نقدشوندگی را مختل کند و سیگنال اشتباه بدهد. بنابراین لازم است سفارش‌های بزرگ به قطعات کوچک‌تر **خرد (Slicing)** شده و در **سطوح قیمتی متعدد** و با **زمان‌بندی مناسب** وارد بازار شوند.

### ۱۶-۲. الگوریتم خرد کردن سفارشات (Order Slicing)

**ورودی‌ها:** حجم کل (\(V_{total}\))، وضعیت بازار، عمق کتاب، حداکثر حجم مجاز در هر سطح (\(V_{max\_level}\)).

**فرمول خرد کردن:**

\[
n = \lceil \frac{V_{total}}{V_{max\_level}} \rceil
\]

**وزن‌دهی پیشنهادی:**

| سطح | فاصله از قیمت پایه | وزن (\(w_i\)) |
|-----|-------------------|--------------|
| ۱ | ±۰.۱٪ | ۰.۳۰ |
| ۲ | ±۰.۲٪ | ۰.۲۵ |
| ۳ | ±۰.۳۵٪ | ۰.۲۰ |
| ۴ | ±۰.۵٪ | ۰.۱۵ |
| ۵ | ±۰.۷٪ | ۰.۱۰ |
| ۶+ | بیشتر | ۰.۰۰ |

**محدودیت‌ها:**
- \(V_{max\_level} = \text{عمق فعلی} \times 0.7\)
- حداقل اندازه هر قطعه: ۵ میلیون تومان

### ۱۶-۳. الگوریتم سفارشات پله‌ای (Stair-Step Orders)

**پارامترهای پویا:**
- **تعداد سطوح (\(N\))**: ۱۰ (بازار باز) / ۷ (بازار بسته)
- **فاصله بین سطوح (\(\Delta\))**: بر اساس ATR و نوسان‌پذیری تعدیل می‌شود.

\[
\Delta = \text{Base\_Spread} \times \text{Volatility\_Multiplier}
\]

**توزیع حجم در سطوح:**

| وضعیت بازار | توزیع حجم |
|-------------|-----------|
| بازار باز | سطح ۱: ۲۵٪، سطح ۲: ۲۰٪، سطح ۳: ۱۵٪، سطح ۴: ۱۲٪، سطح ۵: ۱۰٪، سطح ۶: ۸٪، سطوح ۷-۱۰: ۱۰٪ |
| بازار بسته | سطح ۱: ۲۰٪، سطح ۲: ۱۸٪، سطح ۳: ۱۵٪، سطح ۴: ۱۲٪، سطح ۵: ۱۵٪، سطوح ۶-۷: ۲۰٪ |

### ۱۶-۴. زمان‌بندی ورود سفارش‌ها (Order Timing)

| روش | شرح | کاربرد |
|-----|------|--------|
| **TWAP** | تقسیم حجم به قطعات مساوی در بازه‌های زمانی ثابت | بازار کم‌نوسان |
| **VWAP** | توزیع بر اساس حجم معاملات پیش‌بینی‌شده | بازار پرحجم |
| **Adaptive** | تنظیم پویا بر اساس شرایط لحظه‌ای | حالت پیش‌فرض |

**فرمول پیش‌بینی حجم برای VWAP:**

\[
\text{Vol}_{\text{predicted}}(t) = \text{Vol}_{\text{MA20}} \times \text{Seasonality\_Factor}(t) \times \text{News\_Impact}
\]

- `Vol_MA20`: میانگین حجم ۲۰ روز اخیر
- `Seasonality_Factor`: ضریب فصلی ساعتی/روزانه (از تحلیل داده‌های تاریخی)
- `News_Impact`: ضریب تأثیر اخبار (اگر اخبار مهم باشد > ۱، در غیر این صورت = ۱)

**الگوریتم زمان‌بندی تطبیقی:**

```
Function Execute_Orders(Total_Volume, Market_State):
    if Market_State == "OPEN":
        interval = 10 ثانیه
        slice_size = Total_Volume / 60
    else:
        interval = 30 ثانیه
        slice_size = Total_Volume / 120
    for each level in Order_Book:
        if Order_Filled(level) > 80%:
            Move_Volume_To_Next_Level(level)
```

### ۱۶-۵. کنترل ریسک در اجرای سفارشات

| ریسک | کنترل |
|------|-------|
| پر شدن سریع | انتقال حجم به سطوح دورتر |
| حرکت سریع قیمت | توقف الگوریتم، Kill-Switch |
| کمبود نقدینگی | کاهش اندازه قطعات |
| انحراف از قیمت پایه | بازنگری وزن‌دهی |

**مکانیزم توقف:**
- نوسان > ۲٪ در ۵ دقیقه: کاهش حجم (ضریب ۰.۵×)
- نوسان > ۳٪: توقف کامل و هشدار سطح ۳

### ۱۶-۶. شبه‌کد کامل ماژول اجرا

```
Function Execute_Orders(Total_Volume, Base_Price, Market_State, Volatility, Order_Book_Depth):
    // 1. تعیین تعداد سطوح
    if Market_State == "OPEN":
        Num_Levels = 10
    else:
        Num_Levels = 7
    
    // 2. محاسبه فاصله بین سطوح
    Level_Distance = (ATR(14) / Price) * 100 * Volatility_Multiplier
    
    // 3. محاسبه حجم هر سطح
    Weights = Get_Weights(Market_State)
    for i in 1..Num_Levels:
        Slice_Volume[i] = Total_Volume * Weights[i]
        Max_At_Level = Order_Book_Depth[i] * 0.7
        if Slice_Volume[i] > Max_At_Level:
            Excess = Slice_Volume[i] - Max_At_Level
            Slice_Volume[i] = Max_At_Level
            Slice_Volume[i+1] += Excess
    
    // 4. زمان‌بندی ورود
    Interval = (Market_State == "OPEN") ? 10 : 30
    for each Slice in Slices:
        Place_Order(Slice, Level_Price[i])
        Sleep(Interval)
        if Is_Filled(Slice):
            Remaining = Slice_Volume[i] - Filled
            Slice_Volume[i+1] += Remaining
    
    // 5. کنترل ریسک
    if Price_Change > 0.03:
        Stop_Execution()
        Trigger_Alert(Level=3)
```

### ۱۷-۲. ساختار مدل‌های ML

#### مدل تخمین NAV (رگرسیون خطی)

```python
import numpy as np
from sklearn.linear_model import LinearRegression

def train_nav_model(data):
    # Features: XAU_Return, USDT_Return
    X = np.column_stack((data['xau_return'], data['usdt_return']))
    y = data['nav_return']
    
    model = LinearRegression()
    model.fit(X, y)
    
    # به‌روزرسانی ضرایب
    alpha = model.coef_[0]
    beta = model.coef_[1]
    
    # محدودیت و نرمال‌سازی
    alpha = np.clip(alpha, 0.2, 0.5)
    beta = np.clip(beta, 0.5, 0.8)
    total = alpha + beta
    alpha_final = alpha / total
    beta_final = beta / total
    
    return alpha_final, beta_final
```

#### مدل پیش‌بینی قیمت بازار (XGBoost)

```python
import xgboost as xgb
from sklearn.model_selection import TimeSeriesSplit

def train_price_model(data):
    features = ['nav_estimated', 'xau_current', 'usdt_current', 
                'volume_ma20', 'rsi_14', 'bb_upper', 'bb_lower', 
                'time_of_day', 'day_of_week']
    X = data[features]
    y = data['price_market']
    
    # تقسیم زمانی (Walk-Forward)
    tscv = TimeSeriesSplit(n_splits=5)
    
    model = xgb.XGBRegressor(
        n_estimators=100,
        learning_rate=0.1,
        max_depth=5,
        subsample=0.8,
        colsample_bytree=0.8,
        early_stopping_rounds=10
    )
    
    # آموزش و ارزیابی
    for train_idx, test_idx in tscv.split(X):
        X_train, X_test = X.iloc[train_idx], X.iloc[test_idx]
        y_train, y_test = y.iloc[train_idx], y.iloc[test_idx]
        model.fit(X_train, y_train, eval_set=[(X_test, y_test)], verbose=False)
    
    return model
```

from scipy.stats import mstats

def remove_outliers(data):
    # Winsorization: محدود کردن به صدک 1 و 99
    data['price'] = mstats.winsorize(data['price'], limits=[0.01, 0.01])
    
    # حذف روزهای با نوسان > 5%
    data = data[data['volatility'] < 0.05]
    
    return data

#### معیارهای ارزیابی

```python
from sklearn.metrics import mean_absolute_percentage_error, mean_squared_error, r2_score

def evaluate_model(y_true, y_pred):
    mape = mean_absolute_percentage_error(y_true, y_pred)
    rmse = np.sqrt(mean_squared_error(y_true, y_pred))
    r2 = r2_score(y_true, y_pred)
    
    return {
        'MAPE': mape,
        'RMSE': rmse,
        'R2': r2
    }
```

#### محاسبه Confidence Score

```python
def calculate_confidence(model, X_test, y_test, baseline_rmse):
    y_pred = model.predict(X_test)
    rmse_model = np.sqrt(mean_squared_error(y_test, y_pred))
    
    confidence = max(0, 1 - (rmse_model / baseline_rmse))
    
    return confidence
```

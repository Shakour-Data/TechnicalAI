# 📘 سند جامع و قابل فهم برای هوش مصنوعی: سیستم گراف تصمیم تحلیل تکنیکال پیشرفته (نسخه ۳.۱)

---

## 🧠 راهنمای استفاده از این سند برای هوش مصنوعی

این سند یک **مشخصات فنی کامل** برای پیاده‌سازی سیستم گراف تصمیم تحلیل تکنیکال است. برای اینکه هوش مصنوعی بتواند آن را به‌درستی درک و اجرا کند، ساختار زیر رعایت شده است:

- **زبان فنی و دقیق** – تمام مفاهیم با اصطلاحات استاندارد تعریف شده‌اند.
- **داده‌های ساختاریافته** – از قالب YAML برای نمایش پارامترها، فرمول‌ها و خروجی‌ها استفاده شده است.
- **تعریف صریح متغیرها** – هر متغیر در فرمول‌ها با نام و مفهوم مشخص شده است.
- **قوانین بدون ابهام** – قوانین تصمیم‌گیری به‌صورت شرطی و قطعی بیان شده‌اند.
- **جلوگیری از نگاه به آینده (No Look‑ahead Bias)** – اصل کلیدی در محاسبات روند، صراحتاً ذکر شده است.
- **خروجی نمونه** – نمونه‌های عددی برای فهم نحوه محاسبات ارائه شده است.

هوش مصنوعی باید این سند را به‌عنوان **دستورالعمل اجرایی** تفسیر کند و تمام بخش‌ها را به‌صورت ماژولار پیاده‌سازی نماید.

---

## 🎯 معرفی سیستم

**سیستم گراف تصمیم تحلیل تکنیکال پیشرفته (نسخه ۳.۱)** یک چارچوب کامل، خودکار، علمی، عملیاتی و هوشمند برای تحلیل بازارهای مالی است که از **یادگیری ماشین پیشرفته، یادگیری عمیق، یادگیری تقویتی، پردازش زبان طبیعی و گراف‌های عصبی** برای پیش‌بینی قیمت در بازه‌های **۱ تا ۳۰ جلسه معاملاتی** استفاده می‌کند. این سیستم تمام محاسبات اندیکاتورها، تشخیص الگوها، تحلیل واگرایی‌ها، مدیریت ریسک، ساخت گراف تصمیم و تولید گزارش‌های تحلیلی را به‌صورت خودکار و هوشمند انجام می‌دهد.

## 🎯 اهداف و الزامات کلیدی

### الزامات حیاتی (Must-Have)

1. **سیستم کاملاً خودکار و خودکفا**:
   - محاسبه خودکار **۵۳+ اندیکاتور و اسیلاتور**
   - تشخیص خودکار **الگوهای کلاسیک، هارمونیک، کندل‌استیک و امواج الیوت**
   - بدون نیاز به محاسبات دستی یا ورودی خارجی

2. **مدیریت هوشمند داده‌های حجم**:
   - در صورت عدم وجود داده حجم، حذف خودکار ۱۱ اندیکاتور وابسته به حجم
   - بازتوزیع وزن‌های حذف‌شده به‌طور متناسب بین سایر اندیکاتورها

3. **پیش‌بینی قیمت با یادگیری ماشین پیشرفته**:
   - پیش‌بینی قیمت برای **۱ تا ۳۰ جلسه معاملاتی**
   - استفاده از **LSTM، GRU، Transformer، TCN، Diffusion Models**
   - محاسبه اندیکاتورها بر اساس قیمت‌های پیش‌بینی‌شده
   - شناسایی واگرایی‌های فعلی و آینده

4. **یادگیری تقویتی برای استراتژی معاملاتی**:
   - استفاده از **DQN، PPO، Actor-Critic**
   - یادگیری استراتژی‌های بهینه به‌صورت خودکار

5. **پردازش زبان طبیعی (NLP) برای اخبار**:
   - تحلیل احساسات با **FinBERT، BERT، GPT**
   - تشخیص رویدادهای مهم و تأثیر آنها

6. **ضرایب پویا با یادگیری ماشین**:
   - ضرایب اختصاصی برای هر ابزار مالی
   - به‌روزرسانی روزانه ضرایب با Bayesian Weighting + Meta-Learning

7. **خروجی سه‌گانه**:
   - **مکتب تحلیل** (School of Analysis)
   - **سبک تحلیل** (Analysis Style)
   - **لحن تحلیل** (Analysis Tone)

8. **مدیریت ریسک کامل**:
   - محاسبه حجم موقعیت بر اساس فرمول Kelly Modified + RL
   - تعیین حد ضرر و حد سود بر اساس ATR و ساختار بازار
   - پایش مداوم ریسک با VaR، Expected Shortfall، Conformal Prediction

9. **تشخیص رژیم بازار پیشرفته**:
   - شناسایی ۵ رژیم مختلف بازار با GNN + HMM
   - تطبیق استراتژی با رژیم غالب

10. **ارزیابی عملکرد و Backtesting جامع**:
    - پایش مداوم عملکرد سیستم
    - محاسبه معیارهای عملکرد (Sharpe، Sortino، Profit Factor)
    - بازخورد خودکار برای بهبود

## 📐 مبانی علمی و قوانین حاکم

### ۱. قوانین علمی تحلیل تکنیکال

#### اصل اول: سه فرضیه اصلی
```
فرضیه ۱: قیمت همه‌چیز را تعدیل می‌کند (Price Discounts Everything)
فرضیه ۲: قیمت‌ها در روندها حرکت می‌کنند (Prices Move in Trends)
فرضیه ۳: تاریخ خود را تکرار می‌کند (History Repeats Itself)
```

#### اصل دوم: ترکیب اندیکاتورها
```
قانون ۱: هرگز از یک اندیکاتور به‌تنهایی استفاده نکنید
قانون ۲: حداقل از ۳ اندیکاتور از ۳ خانواده مختلف استفاده کنید
قانون ۳: هم‌جهتی سیگنال‌ها اعتماد را افزایش می‌دهد
قانون ۴: واگرایی‌ها سیگنال‌های قوی برگشت هستند
قانون ۵: حجم معاملات باید برای تأیید سیگنال‌ها استفاده شود
قانون ۶: تایم‌فریم‌های بالاتر برای تعیین روند اصلی اهمیت دارند
```

#### اصل سوم: مدیریت ریسک علمی
```
قانون ۱: ریسک هر معامله نباید از ۱-۲٪ سرمایه تجاوز کند
قانون ۲: نسبت ریسک به بازده حداقل ۱:۲ باشد
قانون ۳: استفاده از حد ضرر (Stop Loss) اجباری است
قانون ۴: حجم معاملات بر اساس اطمینان و فاصله اطمینان تنظیم شود
قانون ۵: در شرایط نوسان بالا، حجم معاملات کاهش یابد
```

### ۲. قوانین گراف تصمیم

```
قانون ۱: هر گره حداقل ۳ یال خروجی دارد
قانون ۲: جمع احتمالات خروجی از هر گره = ۱
قانون ۳: گره‌های تصمیم‌گیری حداکثرکننده EMV هستند
قانون ۴: گره‌های پایانی دارای KPI نهایی هستند
قانون ۵: گراف بدون دور (Acyclic) است
قانون ۶: هر گره تصمیم باید دارای حداقل یک گره ریسک باشد
قانون ۷: خروجی هر گره باید به گره بعدی متصل باشد
```

### ۳. قوانین پیش‌بینی با یادگیری ماشین

```
قانون ۱: Cross-Validation 5-Fold
قانون ۲: داده‌های آموزشی (۶۰٪)، اعتبارسنجی (۲۰٪) و تست (۲۰٪)
قانون ۳: عدم استفاده از داده‌های آینده (Forward-Looking Bias)
قانون ۴: Walk-Forward Analysis برای تأیید مدل
قانون ۵: تست بر روی دوره‌های مختلف بازار (Bull, Bear, Sideways)
قانون ۶: استفاده از Ensemble Methods برای کاهش خطا
قانون ۷: به‌روزرسانی مدل به‌صورت دوره‌ای
قانون ۸: استفاده از Reinforcement Learning با محیط‌های شبیه‌سازی‌شده
قانون ۹: استفاده از Transfer Learning برای دارایی‌های جدید
قانون ۱۰: استفاده از Conformal Prediction برای تضمین‌های آماری
```

**نکته مهم (اصلاح شده):** در محاسبه هر نوع «روند» یا «سری زمانی» (از جمله روند احتمالات)، **فقط از داده‌های موجود تا لحظه محاسبه استفاده می‌شود**. هیچ داده‌ای از آینده (بعد از روز محاسبه) نباید در محاسبات لحاظ شود. این قانون در تمام بخش‌های سیستم اعمال می‌گردد.

## 🧮 سیستم محاسبه خودکار اندیکاتورها

### معماری محاسبه

```yaml
indicator_calculation_engine:
  input_requirements:
    price_data:
      - open: [لیست قیمت‌های باز شدن]
      - high: [لیست بالاترین قیمت‌ها]
      - low: [لیست پایین‌ترین قیمت‌ها]
      - close: [لیست قیمت‌های بسته شدن]
      - timestamp: [لیست زمان‌ها]
    volume_data: [اختیاری - لیست حجم معاملات]
  
  output:
    indicators_matrix: [۵۳+ × تعداد نقاط داده]
    pattern_detection_results: [لیست الگوهای تشخیص‌داده‌شده]
    divergence_results: [لیست واگرایی‌های تشخیص‌داده‌شده]
    scenario_probabilities: [احتمالات ۹ سناریو]
    market_regime: [رژیم بازار فعلی]
  
  validation:
    - بررسی کامل بودن داده‌ها
    - تشخیص وجود/عدم وجود داده‌های حجم
    - حذف خودکار اندیکاتورهای وابسته به حجم در صورت عدم وجود داده
    - بازتوزیع وزن‌های اندیکاتورهای حذف‌شده
    - بررسی سلامت داده‌ها (Outlier Detection)
    - پر کردن داده‌های گم‌شده (Interpolation)
```

### اندیکاتورهای وابسته به حجم (۱۱ مورد)

```
لیست اندیکاتورهای وابسته به حجم:
- MFI (شاخص جریان پول)
- PVO (شاخص قیمت-حجم)
- Volume (حجم معاملات)
- OBV (شاخص تعادل حجم)
```

## 📐 محاسبه قدرت روند و سطوح حمایت/مقاومت

### ۱. قدرت روند (Trend Strength)

#### فرمول اصلی:
```
Trend_Strength = (W1 × ADX_Normalized) + 
                 (W2 × Slope_Strength) + 
                 (W3 × MA_Alignment) + 
                 (W4 × Price_Position) + 
                 (W5 × Momentum_Strength) + 
                 (W6 × Pullback_Quality) + 
                 (W7 × GNN_Correlation_Strength)
```

#### مؤلفه‌ها:

**الف) ADX نرمال‌شده:**
```
ADX_Normalized = min(ADX / 60, 1)
ADX < 20: روند ضعیف
20 < ADX < 40: روند متوسط
ADX > 40: روند قوی
```

**ب) قدرت شیب روند:**
```
Slope_Strength = (EMA_Current - EMA_Previous) / (EMA_Current × Volatility_Adjustment)
Slope > 0.01: شیب صعودی قوی
0.005 < Slope < 0.01: شیب صعودی متوسط
Slope < 0.005: شیب ضعیف یا خنثی
```

**ج) هم‌راستایی میانگین‌های متحرک:**
```
MA_Alignment = (Alignment_Count / 5)
روند صعودی: EMA10 > EMA20 > EMA50 > EMA100 > EMA200
روند نزولی: EMA10 < EMA20 < EMA50 < EMA100 < EMA200
```

**د) موقعیت قیمت نسبت به میانگین‌ها:**
```
Price_Position = (Price - EMA50) / (Price + EMA50) × 2
Price_Position > 0.05: موقعیت قوی صعودی
0.02 < Price_Position < 0.05: موقعیت صعودی متوسط
-0.02 < Price_Position < 0.02: موقعیت خنثی
```

**ه) قدرت مومنتوم:**
```
Momentum_Strength = (RSI_Normalized + MACD_Strength) / 2
RSI_Normalized = |RSI - 50| / 30
MACD_Strength = |MACD_Histogram| / (MACD_Histogram_StdDev)
```

**و) کیفیت اصلاح‌ها:**
```
Pullback_Quality = (1 - Pullback_Depth) × (1 - Pullback_Time)
اصلاح ۰-۲۰٪: عالی
اصلاح ۲۰-۴۰٪: خوب
اصلاح ۴۰-۶۰٪: متوسط
اصلاح > ۶۰٪: ضعیف
```

**ز) قدرت همبستگی GNN:**
```
GNN_Correlation_Strength = (Correlation_with_Bullish_Assets - Correlation_with_Bearish_Assets) / 2
اگر همبستگی با دارایی‌های صعودی قوی باشد → 1.0
اگر همبستگی با دارایی‌های نزولی قوی باشد → 0.0
```

### ۲. قدرت سطوح حمایت/مقاومت (SR Strength)

#### فرمول اصلی:
```
SR_Strength = (W1 × Touch_Count) + 
              (W2 × Time_Validity) + 
              (W3 × Volume_Profile) + 
              (W4 × Volatility_Adjustment) + 
              (W5 × Historical_Significance) + 
              (W6 × Fibonacci_Confluence) + 
              (W7 × Pattern_Support) + 
              (W8 × GNN_Volume_Strength)
```

#### مؤلفه‌ها:

**الف) تعداد برخوردها:**
```
Touch_Count = min(Brkhord_Count / 5, 1)
۵+ برخورد: ۱.۰ (قوی‌ترین)
۳-۴ برخورد: ۰.۶-۰.۸ (متوسط-قوی)
۱-۲ برخورد: ۰.۲-۰.۴ (ضعیف)
```

**ب) اعتبار زمانی:**
```
Time_Validity = min(Timespan / 180, 1)
> ۱۸۰ روز: ۱.۰ (بسیار معتبر)
۶۰-۱۸۰ روز: ۰.۵-۰.۸ (معتبر)
< ۶۰ روز: ۰.۲-۰.۴ (کم‌اعتبار)
```

**ج) پروفایل حجم در سطح:**
```
Volume_Profile = (Volume_at_Level / Average_Volume) × Normalization
Volume > 1.5×Average: قوی (> ۰.۷)
Volume > 1.0×Average: متوسط (۰.۴-۰.۷)
Volume < 1.0×Average: ضعیف (< ۰.۴)
```

**د) تعدیل نوسان:**
```
Volatility_Adjustment = 1 - (ATR / Price)
نوسان کم (ATR/Price < 0.02): تعدیل = ۰.۹۸
نوسان زیاد (ATR/Price > 0.05): تعدیل = ۰.۹۵
```

**ه) اهمیت تاریخی:**
```
Historical_Significance = (Major_High_Count + Major_Low_Count) / 4
```

**و) هم‌گرایی فیبوناچی:**
```
Fibonacci_Confluence = min(Fibonacci_Levels / 3, 1)
۳+ نسبت تلاقی: قوی (> ۰.۷)
۲ نسبت تلاقی: متوسط (۰.۵)
۱ نسبت تلاقی: ضعیف (۰.۳)
```

**ز) پشتیبانی الگوی قیمتی:**
```
Pattern_Support = (Classic_Pattern_Weight + Harmonic_Pattern_Weight) / 2
```

**ح) قدرت حجم GNN:**
```
GNN_Volume_Strength = GNN_Volume_Signal (از گراف عصبی)
اگر حجم در دارایی‌های مرتبط بالا باشد → قوی
اگر حجم در دارایی‌های مرتبط کم باشد → ضعیف
```

### ۲. محاسبه اندیکاتورها بر اساس قیمت‌های پیش‌بینی‌شده

```
فرمول محاسبه اندیکاتورها در آینده:

  P_predicted[t+h] = قیمت پیش‌بینی‌شده برای گام h
  
  مرحله ۲: محاسبه تمام ۵۳+ اندیکاتور با فرمول‌های استاندارد
  Indicator_i[t+h] = f_i(P_predicted[t+1..t+h])
  
  مرحله ۳: برای اندیکاتورهای وابسته به حجم:
  - اگر داده حجم اصلی موجود باشد: استفاده از حجم تاریخی + پیش‌بینی حجم
  - اگر داده حجم موجود نباشد: اندیکاتور محاسبه نشود
  
  مرحله ۴: ثبت تغییرات اندیکاتورها در طول زمان
  ΔIndicator_i[h] = Indicator_i[t+h] - Indicator_i[t+h-1]
  
  مرحله ۵: شناسایی نقاط عطف احتمالی در آینده
  Turning_Point[h] = (Direction_Change_Indicator_i)

نکته مهم:
- برای گام‌های ۱-۵: ترکیب داده‌های واقعی (۲۰۰ روز قبل) + پیش‌بینی
- برای گام‌های ۶-۳۰: استفاده از داده‌های پیش‌بینی‌شده
- برای دوره‌های بلندتر از گام پیش‌بینی: استفاده از داده‌های واقعی
```

### ۲. محاسبه وزن‌های پویا با یادگیری بیزین

```
فرمول اصلی وزن‌دهی با یادگیری بیزین:

W_i = P(Success | Tool_i) × Prior_i / Σ(P(Success | Tool_j) × Prior_j)

که:
- P(Success | Tool_i): احتمال موفقیت با استفاده از ابزار i
  - محاسبه: (Win_Rate_i / 100) × (Sharpe_Ratio_i / 2)
  
- Prior_i: وزن اولیه
  - اندیکاتورهای روند: ۰.۲۸
  - اسیلاتورها: ۰.۲۵
  - اندیکاتورهای حجم (در صورت وجود): ۰.۱۵
  - اندیکاتورهای نوسان: ۰.۱۰
  - اندیکاتورهای پیشرو: ۰.۱۲
  - الگوها: ۰.۱۰
  - مجموع Prior = ۱

- در صورت عدم وجود داده حجم:
  - Prior_Volume = 0
  - بازتوزیع Prior_Volume بین سایر دسته‌ها
```

### ۳. بازتوزیع وزن‌ها در صورت عدم وجود داده حجم

```
الگوریتم بازتوزیع وزن‌ها:

مرحله ۱: شناسایی اندیکاتورهای وابسته به حجم
  - لیست: MFI, PVO, Volume, OBV, A/D, VPT, VWAP, VOSC, VAP, Chaikin A/D, Force Index
  - تعداد: ۱۱ مورد

مرحله ۲: محاسبه وزن کل حذف‌شده
  Weight_Removed = Σ(W_i) برای i در لیست بالا

مرحله ۳: محاسبه وزن باقی‌مانده
  Weight_Remaining = 1 - Weight_Removed

مرحله ۴: بازتوزیع وزن‌های حذف‌شده
  برای هر دسته باقی‌مانده:
    Weight_New_Category = Weight_Old_Category + (Weight_Old_Category / Weight_Remaining) × Weight_Removed

مرحله ۵: نرمال‌سازی نهایی
  - اطمینان از Σ W_i = 1
  - گرد کردن به ۳ رقم اعشار
```

## ⚖️ سیستم مدیریت ریسک (Risk Management System)

### ۱. محاسبه حجم موقعیت (Position Sizing)

```yaml
position_sizing:
  method: "Kelly Criterion Modified + RL"
  
  kelly_formula: |
    f* = (p × b - q) / b
    f* = سهم بهینه سرمایه برای هر معامله
    p = احتمال موفقیت (Win Rate)
    q = احتمال شکست (Loss Rate) = 1 - p
    b = نسبت سود به ضرر (Payoff Ratio)
    
  modified_kelly: |
    f_capped = min(f*, 0.25)  # حداکثر ۲۵٪ سرمایه
    f_final = f_capped × Confidence_Factor
    
    Confidence_Factor:
    - Confidence > 0.80: 1.0
    - Confidence 0.70-0.80: 0.75
    - Confidence 0.60-0.70: 0.50
    - Confidence 0.50-0.60: 0.25
    - Confidence < 0.50: 0.0
    
  rl_adjustment: |
    - استفاده از Reinforcement Learning برای تنظیم حجم
    - RL Agent یاد می‌گیرد که در چه شرایطی حجم را افزایش/کاهش دهد
    - خروجی: ضریب تنظیم حجم (0.5-1.5)
    - Position_Size_Final = f_final × RL_Adjustment_Factor
    
  volatility_adjustment: |
    Position_Size_Adjusted = Position_Size × (Base_Volatility / Current_Volatility)
    Base_Volatility = ATR_20_Median (میانگین ۲۰ روز اخیر)
    Current_Volatility = ATR_14_Current (نوسان فعلی)
    
    اگر Current_Volatility > 1.5 × Base_Volatility:
      Position_Size_Adjusted = Position_Size × 0.5
      
  max_position_limits:
    - Single_Trade_Limit: 10٪ سرمایه
    - Sector_Limit: 20٪ سرمایه
    - Total_Exposure_Limit: 50٪ سرمایه
    - Daily_Loss_Limit: 3٪ سرمایه
    - Weekly_Loss_Limit: 7٪ سرمایه
```

### ۲. تعیین حد ضرر (Stop Loss)

```yaml
stop_loss_placement:
  method: "ATR + Structure Based + RL"
  
  atr_based: |
    Stop_Loss = Entry_Price - (K × ATR)
    K = 1.5 برای روند قوی (Trend_Strength > 0.7)
    K = 2.0 برای روند متوسط (Trend_Strength 0.5-0.7)
    K = 2.5 برای روند ضعیف (Trend_Strength < 0.5)
    
  structure_based: |
    Stop_Loss = نزدیک‌ترین سطح حمایت - (0.5 × ATR)
    یا
    Stop_Loss = زیر آخرین Swing Low - (0.5 × ATR)
    
  rl_adjustment: |
    - RL Agent یاد می‌گیرد که حد ضرر را بر اساس شرایط بازار تنظیم کند
    - خروجی: ضریب تنظیم حد ضرر (0.8-1.2)
    - Stop_Loss_Final = Stop_Loss × RL_Stop_Loss_Factor
    
  combination: |
    Stop_Loss_Final = min(ATR_Based, Structure_Based)
    # استفاده از نزدیک‌ترین حد ضرر (محتاطانه‌تر)
    
  maximum_stop_distance: |
    Max_Stop_Distance = 3 × ATR
    اگر Stop_Loss > Max_Stop_Distance:
      Stop_Loss = Entry_Price - (3 × ATR)
      
  minimum_stop_distance: |
    Min_Stop_Distance = 0.5 × ATR
    اگر Stop_Loss < Min_Stop_Distance:
      Stop_Loss = Entry_Price - (0.5 × ATR)
      # برای جلوگیری از نوسانات عادی بازار
```

## 🧮 محاسبه احتمالات نهایی و تجمعی

### ۱. احتمال صعودی نهایی

```
P_Bull_Final = α × P_Bull_Current + (1-α) × P_Bull_Forecast

که:
α = 0.5 (وزن وضعیت فعلی، قابل تنظیم با ML)

P_Bull_Current = Σ(W_i_Current × Signal_Bull_i_Current) + Σ(Divergence_Impact_i_Current) + GNN_Bullish_Impact + NLP_Bullish_Impact

P_Bull_Forecast = Σ_{h=1}^{30} [W_Forecast_h × (Σ(W_i_Forecast_h × Signal_Bull_i_Forecast_h) + Σ(Divergence_Impact_i_Forecast_h))]
```

### ۲. احتمال نزولی نهایی

```
P_Bear_Final = α × P_Bear_Current + (1-α) × P_Bear_Forecast
```

### ۳. احتمال خنثی نهایی

```
P_Neutral_Final = 1 - (P_Bull_Final + P_Bear_Final)
```

### ۴. وزن‌دهی به گام‌های پیش‌بینی با تابع زوال نمایی دوگانه

این تابع **فقط برای محاسبه وزن اهمیت گام‌های پیش‌بینی در محاسبه P_Bull_Forecast و P_Bear_Forecast** استفاده می‌شود، **نه برای محاسبه روند تاریخی احتمالات**.

```
Decay_Factor_h = α × exp(-h/τ₁) + (1-α) × exp(-h/τ₂)

که:
- h: شماره گام پیش‌بینی (۱ تا ۳۰)
- α = 0.7 (وزن جزء کوتاه‌مدت)
- τ₁ = 5 (ثابت زمانی کوتاه‌مدت)
- τ₂ = 20 (ثابت زمانی بلندمدت)

W_Forecast_h = Decay_Factor_h / Σ_{j=1}^{30} Decay_Factor_j
```

> **توجه:** این فرمول فقط برای ترکیب پیش‌بینی‌های آینده در محاسبه احتمالات فعلی است. **برای روند ۳۰ روز گذشته هیچ‌گونه زوال یا ترکیب مصنوعی به کار نمی‌رود** – روند از مقادیر واقعی محاسبه‌شده در هر روز تاریخی استخراج می‌شود.

### ۵. محاسبه سناریوی نهایی

```
برای هر سناریوی S (۱ تا ۹):
P_Scenario_S = P_Bull_Final × Conditional_Probability_S_Bull + 
               P_Bear_Final × Conditional_Probability_S_Bear +
               P_Neutral_Final × Conditional_Probability_S_Neutral

سناریوی نهایی = argmax(P_Scenario_S)
اطمینان نهایی = P_Scenario_S / Σ P_Scenario_i
```

### ۶. محاسبه احتمالات تجمعی (در همان روز)

> **تعریف صحیح:** احتمال تجمعی یک سناریو در یک روز مشخص، **جمع احتمالات اختصاصی سناریوهای هم‌دسته از شدیدترین به خفیف‌ترین** در **همان روز** است.

#### فرمول‌های احتمالات تجمعی (در هر روز t):

**دسته صعودی (Bullish) – از شدید به خفیف:**
```
Cum_Shock_Up(t)     = P_Shock_Up(t)
Cum_Accel_Bull(t)   = P_Shock_Up(t) + P_Accel_Bull(t)
Cum_Strong_Bull(t)  = P_Shock_Up(t) + P_Accel_Bull(t) + P_Strong_Bull(t)
Cum_Weak_Bull(t)    = P_Shock_Up(t) + P_Accel_Bull(t) + P_Strong_Bull(t) + P_Weak_Bull(t)
```

**دسته رنج (Neutral):**
```
Cum_Range(t) = P_Range(t)
```

**دسته نزولی (Bearish) – از شدید به خفیف:**
```
Cum_Shock_Down(t)     = P_Shock_Down(t)
Cum_Accel_Bear(t)     = P_Shock_Down(t) + P_Accel_Bear(t)
Cum_Strong_Bear(t)    = P_Shock_Down(t) + P_Accel_Bear(t) + P_Strong_Bear(t)
Cum_Weak_Bear(t)      = P_Shock_Down(t) + P_Accel_Bear(t) + P_Strong_Bear(t) + P_Weak_Bear(t)
```

#### احتمالات تجمعی دسته‌ای (Cumulative Probabilities):

در هر روز t:
```
P_Bullish_Cumulative(t) = Cum_Weak_Bull(t)   (همان جمع کل سناریوهای صعودی)
P_Neutral_Cumulative(t) = Cum_Range(t)
P_Bearish_Cumulative(t) = Cum_Weak_Bear(t)   (همان جمع کل سناریوهای نزولی)
```

#### احتمالات تجمعی وزن‌دار با شدت (Severity-Weighted):

```
P_Bullish_Weighted(t) = Σ (P_Scenario_i(t) × Severity_Factor_i) برای i = 1 تا 4

Severity_Factor:
- شوک صعودی (سناریو ۱): 1.0
- صعودی شتاب‌دار (سناریو ۲): 0.8
- صعودی قوی (سناریو ۳): 0.6
- صعودی خفیف (سناریو ۴): 0.3

P_Bearish_Weighted(t) = Σ (P_Scenario_i(t) × Severity_Factor_i) برای i = 6 تا 9

Severity_Factor:
- شوک نزولی (سناریو ۹): 1.0
- نزولی شتاب‌دار (سناریو ۸): 0.8
- نزولی قوی (سناریو ۷): 0.6
- نزولی خفیف (سناریو ۶): 0.3
```

#### مثال محاسبه در یک روز مشخص:

فرض کنید احتمالات اختصاصی در روز t به این صورت است:

| سناریو | احتمال اختصاصی |
|--------|---------------|
| شوک صعودی | ۰.۱۲ |
| صعودی شتاب‌دار | ۰.۱۹ |
| صعودی قوی | ۰.۳۲ |
| صعودی خفیف | ۰.۱۶ |
| رنج | ۰.۱۵ |
| نزولی خفیف | ۰.۱۰ |
| نزولی قوی | ۰.۱۰ |
| نزولی شتاب‌دار | ۰.۰۶ |
| شوک نزولی | ۰.۰۴ |

**محاسبه احتمالات تجمعی در همان روز:**
- شوک صعودی: `Cum = ۰.۱۲`
- صعودی شتاب‌دار: `Cum = ۰.۱۲ + ۰.۱۹ = ۰.۳۱`
- صعودی قوی: `Cum = ۰.۱۲ + ۰.۱۹ + ۰.۳۲ = ۰.۶۳`
- صعودی خفیف: `Cum = ۰.۱۲ + ۰.۱۹ + ۰.۳۲ + ۰.۱۶ = ۰.۷۹`
- رنج: `Cum = ۰.۱۵`
- شوک نزولی: `Cum = ۰.۰۴`
- نزولی شتاب‌دار: `Cum = ۰.۰۴ + ۰.۰۶ = ۰.۱۰`
- نزولی قوی: `Cum = ۰.۰۴ + ۰.۰۶ + ۰.۱۰ = ۰.۲۰`
- نزولی خفیف: `Cum = ۰.۰۴ + ۰.۰۶ + ۰.۱۰ + ۰.۱۰ = ۰.۳۰`

**احتمالات تجمعی دسته‌ای:**
- Bullish Cumulative = ۰.۷۹
- Neutral Cumulative = ۰.۱۵
- Bearish Cumulative = ۰.۳۰

**نکته:** در این مثال مجموع احتمالات اختصاصی = ۰.۱۲+۰.۱۹+۰.۳۲+۰.۱۶+۰.۱۵+۰.۱۰+۰.۱۰+۰.۰۶+۰.۰۴ = ۱.۲۴؛ این بدان معناست که احتمالات نرمال نشده‌اند. در عمل، احتمالات باید به‌گونه‌ای نرمال شوند که جمع آنها برابر ۱ باشد (مثلاً با تقسیم بر مجموع). اما برای نشان دادن قاعده پله‌ای، این اعداد صرفاً نمونه هستند.

### ۱. تعریف و روش محاسبه

**روند احتمالات**، نمایش **تغییرات احتمال اختصاصی و تجمعی هر سناریو در ۳۰ روز گذشته** است.

**شرط اصلی:** برای هر روز `t` (که t از ۳۰ روز پیش تا امروز متغیر است)، تمام احتمالات (اختصاصی و تجمعی) **فقط با استفاده از داده‌های موجود تا انتهای آن روز** محاسبه می‌شوند. هیچ داده‌ای از روزهای بعد از `t` در محاسبه احتمالات روز `t` استفاده نمی‌شود. این اصل «عدم استفاده از داده‌های آینده» (No Look-ahead Bias) به‌طور کامل رعایت می‌شود.

**فرآیند محاسبه برای هر روز t:**
1. دریافت داده‌های قیمت/حجم/اخبار و... تا انتهای روز t (حداکثر تا روز t).
2. محاسبه تمام ۵۳+ اندیکاتور بر اساس داده‌های تا روز t.
3. تشخیص الگوها، واگرایی‌ها و رژیم بازار بر اساس داده‌های تا روز t.
4. محاسبه احتمالات اختصاصی ۹ سناریو (با استفاده از مدل‌های آموزش‌دیده بر روی داده‌های قبل از روز t).
5. محاسبه احتمالات تجمعی بر اساس قاعده پله‌ای در همان روز t.
6. ثبت نتایج در جدول روند.

**نتایج برای هر روز t شامل:**
- احتمال اختصاصی هر ۹ سناریو
- احتمال تجمعی هر ۹ سناریو (بر اساس قاعده پله‌ای)
- احتمال تجمعی دسته‌ای (Bullish, Neutral, Bearish)

### ۲. قالب خروجی روند

خروجی به‌صورت **جدول ۳۰ ردیفه** (هر ردیف مربوط به یک روز) ارائه می‌شود. هر ردیف شامل ستون‌های زیر است:

| تاریخ | روز | شوک صعودی (اختصاصی/تجمعی) | صعودی شتاب‌دار (اختصاصی/تجمعی) | ... | رنج | ... | شوک نزولی (اختصاصی/تجمعی) | Bullish Cumulative | Bearish Cumulative |

**مثال جدول (نمایش ۵ روز اول از ۳۰ روز):**

| تاریخ | روز | شوک صعودی (اختصاصی/تجمعی) | صعودی شتاب‌دار (اختصاصی/تجمعی) | صعودی قوی (اختصاصی/تجمعی) | صعودی خفیف (اختصاصی/تجمعی) | رنج | نزولی خفیف (اختصاصی/تجمعی) | نزولی قوی (اختصاصی/تجمعی) | نزولی شتاب‌دار (اختصاصی/تجمعی) | شوک نزولی (اختصاصی/تجمعی) | Bullish Cum | Bearish Cum |

### ۳. تحلیل روند احتمالات

پس از تولید جدول، سیستم به‌صورت خودکار **تحلیل روند** را ارائه می‌دهد:

- **روند احتمال اختصاصی هر سناریو:** افزایشی / کاهشی / نوسانی / ثابت
- **روند احتمال تجمعی هر سناریو:** بر اساس تغییرات تجمعی (که خود به تغییرات اختصاصی وابسته است)
- **تغییرات معنادار:** شناسایی نقاط عطف (مثلاً زمانی که احتمال اختصاصی یک سناریو بیش از ۰.۰۵ تغییر می‌کند)
- **هم‌گرایی/واگرایی:** بررسی همبستگی روند احتمالات با روند قیمت و سایر متغیرها

**توجه:** تحلیل روند صرفاً توصیفی است و از هیچ مدل یا فرمول مصنوعی برای تولید روند استفاده نمی‌شود.

### ۴. کاربرد روند احتمالات

- **پایش تغییرات احتمالات:** مشاهده اینکه چگونه احتمالات سناریوها در طول زمان تغییر کرده‌اند.
- **تشخیص تغییر رژیم:** افزایش ناگهانی احتمال یک سناریوی خاص می‌تواند نشان‌دهنده تغییر رژیم بازار باشد.
- **ارزیابی عملکرد مدل:** مقایسه احتمالات گذشته با نتایج واقعی.
- **تولید متن تحلیل:** استفاده از روند برای توضیح «چرا این تصمیم» و «تغییرات اخیر».

## 📊 سیستم ارزیابی عملکرد (Performance Evaluation System)

### ۱. معیارهای عملکرد

```yaml
performance_metrics:
  returns:
    - total_return
    - annualized_return
    - cagr (Compound Annual Growth Rate)
    - monthly_return_average
    - monthly_return_stddev
    
  risk_adjusted_returns:
    - sharpe_ratio
      - فرمول: (Return - Risk_Free_Rate) / StdDev
      - هدف: > 1.5
    - sortino_ratio
      - فرمول: (Return - Risk_Free_Rate) / Downside_StdDev
      - هدف: > 2.0
    - calmar_ratio
      - فرمول: Annual_Return / Max_Drawdown
      - هدف: > 1.5
    - treynor_ratio
      - فرمول: (Return - Risk_Free_Rate) / Beta
    
  trading_metrics:
    - win_rate (نرخ برد)
      - فرمول: تعداد معاملات سودده / کل معاملات
      - هدف: > 55%
    - profit_factor
      - فرمول: مجموع سودها / مجموع ضررها
      - هدف: > 1.5
    - average_win_loss_ratio
      - فرمول: میانگین سود / میانگین ضرر
      - هدف: > 1.5
    - expectancy
      - فرمول: (Win_Rate × Avg_Win) - (Loss_Rate × Avg_Loss)
      - هدف: > 0 (مثبت)
    
  drawdown_metrics:
    - max_drawdown
      - هدف: < 15%
    - max_drawdown_duration
      - هدف: < 30 روز
    - recovery_factor
      - فرمول: Total_Return / Max_Drawdown
      - هدف: > 2.0
    
  risk_metrics:
    - value_at_risk_var_95
    - expected_shortfall
    - beta (نسبت به بازار)
    - alpha (بازده اضافی)
    - correlation_to_market
```

### ۲. فرآیند Backtesting

```yaml
backtesting_framework:
  walk_forward_analysis:
    - داده‌ها به دوره‌های ۶ ماهه تقسیم می‌شوند
    - برای هر دوره: آموزش با ۵ سال داده قبلی
    - تست با ۶ ماه داده جدید
    - میانگین‌گیری از نتایج همه دوره‌ها
    
  monte_carlo_simulation:
    - ۱۰۰۰ بار اجرای تصادفی
    - ۱۰۰۰ مسیر قیمت تصادفی
    - محاسبه توزیع بازده‌ها
    - محاسبه VaR و ES
    
  bootstrap_analysis:
    - نمونه‌برداری تصادفی از معاملات
    - ۱۰۰۰ نمونه‌برداری
    - توزیع معیارهای عملکرد
    
  out_of_sample_testing:
    - ۲۰٪ داده‌های تست که در آموزش استفاده نشده‌اند
    - گزارش عملکرد بر روی داده‌های جدید
    
  crisis_testing:
    - COVID-19 (2020)
    - Financial Crisis (2008)
    - Crypto Winter (2018, 2022)
    - Flash Crash (2010)
    - Dotcom Bubble (2000)
    
  rl_backtesting:
    - شبیه‌سازی محیط‌های معاملاتی
    - تست استراتژی‌های RL
    - ارزیابی عملکرد RL Agent
```

### ۳. پایش عملکرد زنده (Live Performance Monitoring)

```yaml
live_monitoring:
```

### ۱. یادگیری تقویتی (Reinforcement Learning)

```yaml
reinforcement_learning:
  frameworks:
    - Deep Q-Network (DQN)
      - کاربرد: یادگیری استراتژی معاملاتی
      - State: وضعیت بازار + اندیکاتورها + GNN Features + NLP Features
      - Action: BUY, SELL, HOLD
      - Reward: سود/ضرر + مدیریت ریسک
      - ساختار: 2 Hidden Layers (128, 64)
      - Learning Rate: 0.001
      - Discount Factor: 0.99
      - Replay Buffer: 10000
      - Epsilon-Greedy: 0.1 → 0.01 (Decay)
      
    - Proximal Policy Optimization (PPO)
      - کاربرد: یادگیری استراتژی‌های پیچیده
      - مزیت: پایدارتر از DQN
      - ساختار: Actor-Critic با 2 Hidden Layers
      - Learning Rate: 0.0003
      - Clip Range: 0.2
      - Update Frequency: هر 5 Epochs
      
    - Actor-Critic Methods
      - کاربرد: یادگیری همزمان سیاست و ارزش
      - Actor: انتخاب اقدام
      - Critic: ارزیابی ارزش
      - ساختار: Actor (64, 32) + Critic (64, 32)
      
    - Multi-Agent RL
      - کاربرد: شبیه‌سازی تعامل معامله‌گران
      - مزیت: درک رفتار بازار
      - تعداد Agents: 5-10
      - تعامل: رقابت + همکاری
      
  environments:
    - Gymnasium Custom Environment
      - State Space: [قیمت، اندیکاتورها، GNN Features, NLP Features]
      - Action Space: [BUY, SELL, HOLD]
      - Reward Function: سود/ضرر + پنالتی ریسک
      - Max Steps: 30 (1-30 روز)
      
    - Backtesting Environment
      - استفاده از داده‌های تاریخی
      - شبیه‌سازی معاملات
      - محاسبه بازده و ریسک
      
  training_process:
    - Pre-training with Historical Data
    - Fine-tuning with Real-Time Data
```

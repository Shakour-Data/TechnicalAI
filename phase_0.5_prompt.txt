# TechnicalAI Phase 0.5: Foundation Implementation

## Objective
Establish the foundational infrastructure for ML/Time Series Analysis features including data backfill, calibration, scenario labeling, feature engineering, baseline calculation, model persistence, async job management, class imbalance handling, stationary bootstrap, regime classification, and validation pipeline.

## CRITICAL DESIGN DECISIONS (must be settled before any phase)
- Scenario label definition is the single source of truth. All components (labeler, decision graph, probability trend) MUST use identical thresholds. See Task 0.3 for final definition.
- Feature limit is exactly 37. Any new features from Phase 2 must REPLACE existing features, not augment. Explicit replacement mapping required.
- Ensemble weighting method: inverse-variance weighting based on out-of-sample performance.
- Path contribution aggregation: simple average of 3 branch path contributions per scenario.

- Output: Complete historical dataset for all symbols + historical probability snapshots

### 0.2 Branch Drift Calibration

- Store calibrated parameters per symbol/sector
- Ensure parameters are updated weekly
- Validate against out-of-sample performance
- Output: Calibrated drift parameters for decision graph edges

### 0.3 Mutual Exclusive Scenario Labeler (SC1-SC9) — FINAL DEFINITION
- This is the single source of truth for all scenario labels. Every other phase MUST use these exact thresholds.
- Implement scenario labeling based on 5-day forward returns:
  * SC1: < -10% (Bearish Shock)
  * SC2: -10% to -5% (Accelerating Bear)
  * SC3: -5% to -2% (Strong Bear)
  * SC4: -2% to -0.5% (Weak Bear)
  * SC5: -0.5% to +0.5% (Range-bound)
  * SC6: +0.5% to +2% (Weak Bull)
  * SC7: +2% to +5% (Strong Bull)
  * SC8: +5% to +10% (Accelerating Bull)
  * SC9: > +10% (Bullish Shock)
- Thresholds selected to match existing decision-graph.ts node semantics (SC1=most bearish, SC9=most bullish, SC5=neutral)
- Ensure no overlap between scenarios (mutually exclusive and collectively exhaustive)
- Output: Scenario labels for all historical data points + historical probability snapshots

### 0.4 VDSS Feature Builder v2 (Exactly 37 Features)
- Feature extraction MUST output exactly 37 features. Any new features must REPLACE existing ones (see Phase 2 Task 2.5 for replacement mapping).
- Composition:
  * 16 VDSS features (f_rsi, f_mfi, f_cci, s_adx, f_macd, f_stoch, s_bb, s_ma21, s_ma100, s_ema, s_atr, s_trend, s_sr, f_stoch_cross, f_macd_cross, f_div)
  * 12 distance features (normalized price distances to key levels)
  * 4 edge probability features (up, down, pullback, risk — computed from decision graph edge weights)
  * 3 group path contributions: simple average of path contributions across the 3 branches (trend, breakout, reversal). Method: arithmetic mean of all 9 pathContributions per group.
  * 1 regime feature (current market regime: bull/bear/neutral/volatile)
  * 1 pattern feature (detected candlestick pattern)
- Aggregation method for path contributions MUST be simple average, not weighted or selective.
- Ensure feature extraction is deterministic and reproducible
- Add feature validation and normalization
- Output: Feature vectors with exactly 37 elements

### 0.8 Class Imbalance Handler — TIME SERIES SAFE
- **DO NOT use SMOTE, ADASYN, or any interpolation-based oversampling.** These methods assume i.i.d. data and create artificial samples that violate temporal structure, introducing data leakage.
- Use class weighting only: pass class_weight='balanced' to logistic regression and LightGBM.
- Add threshold moving for probability calibration (adjust decision threshold based on validation performance).
- Add evaluation metrics for imbalanced data (precision, recall, F1, PR-AUC).
- Output: Calibrated models with class weighting

### 0.9 Stationary Bootstrap Validator
- Implement stationary bootstrap for time series validation
- Add block bootstrap with geometrically distributed block sizes (min 5, max 25)
- Ensure temporal dependence is preserved
- Implement confidence interval calculation using **percentile method only** (NOT BCa — BCa assumes i.i.d. bootstrap samples and is invalid for block bootstrap)
- Output: Statistically valid performance estimates

### 0.10 Regime Classification Engine

- Output: Market regime classifications (bull/bear/neutral/volatile)

### 0.11 Ensemble Model Saving

- Create ensemble prediction aggregation

- Output: Saved ensemble models with performance metrics

### 0.12 Validation Pipeline Implementation
- Implement walk-forward validation only (no random splits)
- Add expanding window and sliding window options
- Implement proper train/validation/test separation
- Add performance tracking over time
- Ensure no data leakage in validation
- Output: Validation results with statistical significance

    35→## 11. Sequence Diagram (UML §17.2)
    36→
    37→> **نمودار دنباله‌ای (Sequence Diagram)** یکی از مهم‌ترین نمودارهای رفتاری UML است که ترتیب زمانی تبادل پیام‌ها بین اشیاء را نشان می‌دهد. در سامانه تحلیل تکنیکال بورس تهران، این نمودار چگونگی تعامل کاربر، رابط کاربری، موتور تحلیل، و سرویس‌های هوش مصنوعی را در جریان تحلیل یک نماد بورسی مشخص می‌کند.

    41→### 11.1 Level 1 — High-Level Successful Analysis Flow
    42→
    43→> **سطح اول:** جریان اصلی موفق تحلیل از انتخاب نماد توسط کاربر تا نمایش نتایج در صفحه. این نمودار نگاهی سطح‌بالا به تعاملات اصلی سیستم ارائه می‌دهد و مسیر پردازش داده از TSE API تا پاسخ نهایی را نشان می‌دهد.
    44→
    45→```plantuml
    46→@startuml
    47→title Level 1: High-Level Successful Analysis Flow\nبورس تهران — جریان تحلیل موفق
    48→
    49→actor User
    50→participant "page.tsx" as page <<boundary>>
    51→participant "analysis_api" as api <<control>>
    52→participant "tse_api" as tse <<entity>>
    53→participant "ta_engine" as ta <<control>>
    54→
    55→User -> page : selectSymbol(symbol)
    56→activate page
    57→
    58→page -> api : GET /api/analysis?symbol={symbol}
    59→activate api
    60→
    61→api -> tse : fetchCandlestick(symbol, range)
    62→activate tse
    63→tse --> api : CandlestickData[]
    64→deactivate tse
    65→
    66→api -> ta : analyze(CandlestickData[])
    67→activate ta
    68→ta --> api : TAResult
    69→deactivate ta
    70→
    71→api --> page : { taResult, meta }
    72→deactivate api
    73→
    74→page --> User : renderAnalysis(TAResult)
    75→deactivate page
    76→
    77→@enduml
    78→```
    79→
    80→| Step | Message | From → To | Semantics |
    81→|---|---|---|---|
    82→| 1 | `selectSymbol(symbol)` | User → page.tsx | User initiates analysis |
    83→| 2 | `GET /api/analysis?symbol=` | page.tsx → analysis_api | HTTP request to API route |
    84→| 3 | `fetchCandlestick(symbol, range)` | analysis_api → tse_api | Fetch market data from TSE |
    85→| 4 | return `CandlestickData[]` | tse_api → analysis_api | OHLCV data returned |
    86→| 5 | `analyze(CandlestickData[])` | analysis_api → ta_engine | Run technical analysis |
    87→| 6 | return `TAResult` | ta_engine → analysis_api | Indicators, trend, S/R results |
    88→| 7 | return `{ taResult, meta }` | analysis_api → page.tsx | JSON response to client |
    89→| 8 | `renderAnalysis(TAResult)` | page.tsx → User | UI renders analysis |

    93→### 11.2 Level 2 — Detailed Technical Analysis with Regime Detection
    94→
    95→> **سطح دوم:** جزئیات تعاملات داخلی موتور تحلیل تکنیکال شامل محاسبه اندیکاتورها، تشخیص رژیم بازار، و تحلیل سطوح حمایت/مقاومت. در این سطح، فراخوانی‌های داخلی ta_engine و regime_engine با ترتیب دقیق نشان داده می‌شوند و نحوه ترکیب نتایج توسط تصمیم‌گیرنده بیزی مشخص می‌گردد.
    96→
    97→```plantuml
    98→@startuml
    99→title Level 2: Technical Analysis with Regime Detection\nتحلیل تکنیکال با تشخیص رژیم
   100→
   101→actor User
   102→participant "page.tsx" as page <<boundary>>
   103→participant "analysis_api" as api <<control>>
   104→participant "tse_api" as tse <<entity>>
   105→participant "ta_engine" as ta <<control>>
   106→participant "sr_analyzer" as sr <<entity>>
   107→participant "regime_engine" as regime <<control>>
   108→participant "volume_profile" as vp <<entity>>
   109→participant "bayesian_weights" as bw <<entity>>
   110→
   111→User -> page : selectSymbol(symbol)
   112→activate page
   113→
   114→page -> api : GET /api/analysis?symbol={symbol}
   115→activate api
   116→
   117→api -> tse : fetchCandlestick(symbol, range)
   118→activate tse
   119→tse --> api : candles[]
   120→deactivate tse
   121→
   122→api -> tse : fetchDailySnapshots(symbol)
   123→activate tse
   124→tse --> api : snapshots[]
   125→deactivate tse
   126→
   127→== Technical Analysis Engine ==
   128→
   129→api -> ta : analyze(candles[], snapshots[])
   130→activate ta
   131→
   132→ta -> ta : calcIndicators(candles[])
   133→note right: RSI, MACD, Stochastic,\nBB, ATR, ADX, OBV, MFI
   134→
   135→ta -> ta : calcTrend(indicators)
   136→note right: TrendDirection,\nTrendStrength
   137→
   138→ta -> sr : analyzeSupportResistance(candles[], indicators)
   139→activate sr
   140→sr -> vp : approximateVolumeProfile(candles[])
   141→activate vp
   142→vp --> sr : VolumeProfile{vpoc, vlab, pocNodes}
   143→deactivate vp
   144→sr --> ta : SRLevels{supports, resistances, strengths}
   145→deactivate sr
   146→
   147→== Regime Detection ==
   148→
   149→api -> regime : detectRegime(candles[], indicators)
   150→activate regime
   151→
   152→regime -> regime : fuzzyRegimeDetector(indicators)
   153→note right: Fuzzy memberships:\nbullish, bearish, sideways
   154→
   155→regime -> regime : propagateMarkov(prevState)
   156→note right: Markov chain transition\nprobabilities
   157→
   158→regime -> regime : adaptiveWeightedVote(fuzzy, markov)
   159→note right: Weighted ensemble vote\nwith adaptive λ
   160→
   161→regime --> api : RegimeResult{label, confidence, transition}
   162→deactivate regime
   163→
   164→regime -> bw : computeHistoricalProbabilities(regime)
   165→activate bw
   166→bw -> bw : buildTrendFromDailySnapshots(snapshots[])
   167→bw --> regime : HistoricalProbs{bull, bear, neutral}
   168→deactivate bw
   169→
   170→== Compile Result ==
   171→
   172→ta --> api : TAResult{indicators, trend, sr, signals}
   173→deactivate ta
   174→
   175→api --> page : { taResult, regimeResult, meta }
   176→deactivate api
   177→
   178→page --> User : renderFullAnalysis()

   180→
   181→@enduml

   184→| Phase | Internal Calls | Output |
   185→|---|---|---|

   187→| **Trend Calculation** | `calcTrend(indicators)` | `TrendDirection + TrendStrength` |
   188→| **S/R Analysis** | `analyzeSupportResistance()` → `approximateVolumeProfile()` | `SRLevels + VolumeProfile` |
   189→| **Regime Detection** | `fuzzyRegimeDetector()` + `propagateMarkov()` + `adaptiveWeightedVote()` | `RegimeResult{label, confidence}` |

   194→### 11.3 Level 3 — Full Interaction with Async, Exceptions, and Parallelization
   195→
   196→> **سطح سوم:** کامل‌ترین نمودار دنباله‌ای شامل بلوک‌های همزمان (par)، جایگزین (alt)، اختیاری (opt)، و مدیریت استثناها. این سطح شامل تولید متن هوش مصنوعی با منطق تلاش مجدد (retry)، پیش‌بینی یادگیری ماشین با بازگشت به روش اکتشافی در صورت شکست، و همه تعاملات سیستم برای یک تحلیل کامل است.
   197→
   198→```plantuml
   199→@startuml
   200→title Level 3: Full Interaction — Async, Exceptions, Parallelism\nتعامل کامل با مدیریت خطا و موازی‌سازی
   201→
   202→actor User
   203→participant "page.tsx" as page <<boundary>>
   204→participant "analysis_api" as api <<control>>
   205→participant "tse_api" as tse <<entity>>
   206→participant "ta_engine" as ta <<control>>
   207→participant "sr_analyzer" as sr <<entity>>
   208→participant "volume_profile" as vp <<entity>>
   209→participant "regime_engine" as regime <<control>>
   210→participant "ml_engine" as ml <<control>>
   211→participant "ml_logistic" as lr <<entity>>
   212→participant "msl_v4" as msl <<control>>
   213→participant "vdes_api" as vdes <<boundary>>
   214→participant "zai_shared" as zai <<entity>>
   215→participant "ai_postprocess" as aip <<control>>
   216→participant "msl_feedback" as fb <<entity>>
   217→participant "bayesian_weights" as bw <<entity>>
   218→participant "decision_graph" as dg <<control>>
   219→participant "safe_storage" as store <<entity>>
   220→
   221→User -> page : selectSymbol(symbol)
   222→activate page
   223→
   224→page -> api : POST /api/analysis { symbol }
   225→activate api
   226→
   227→api -> store : acquireLock(analysisKey)
   228→activate store
   229→store --> api : lockGranted
   230→deactivate store
   231→
   232→== Parallel Data Fetching ==
   233→
   234→par [Fetch Market Data]
   235→  api -> tse : fetchCandlestick(symbol, range)
   236→  activate tse
   237→  tse --> api : candles[]
   238→  deactivate tse
   239→else [Fetch Snapshots]
   240→  api -> tse : fetchDailySnapshots(symbol)
   241→  activate tse
   242→  tse --> api : snapshots[]
   243→  deactivate tse
   244→end
   245→
   246→== Technical Analysis (Core) ==
   247→
   248→api -> ta : analyze(candles[], snapshots[])
   249→activate ta
   250→
   251→ta -> ta : calcIndicators(candles[])
   252→
   253→ta -> ta : calcTrend(indicators)
   254→
   255→ta -> sr : analyzeSupportResistance(candles[], indicators)
   256→activate sr
   257→
   258→sr -> vp : approximateVolumeProfile(candles[])
   259→activate vp
   260→vp --> sr : VolumeProfile{vpoc, vlab}
   261→deactivate vp
   262→
   263→sr --> ta : SRLevels
   264→deactivate sr
   265→
   266→ta --> api : TAResult
   267→deactivate ta
   268→
   269→== Regime Detection ==
   270→
   271→api -> regime : detectRegime(candles[], indicators)
   272→activate regime
   273→
   274→regime -> regime : fuzzyRegimeDetector(indicators)
   275→regime -> regime : propagateMarkov(prevState)
   276→regime -> regime : adaptiveWeightedVote(fuzzy, markov)
   277→
   278→regime -> bw : computeHistoricalProbabilities(regime)
   279→activate bw
   280→bw -> bw : buildTrendFromDailySnapshots(snapshots[])
   281→bw --> regime : HistoricalProbs
   282→deactivate bw
   283→
   284→regime --> api : RegimeResult
   285→deactivate regime
   286→
   287→== ML Prediction with Fallback ==
   288→
   289→api -> ml : trainAndPredict(candles[], regime, indicators)
   290→activate ml
   291→
   292→opt [Model exists in cache]
   293→  ml -> store : getCachedModel(symbol)
   294→  activate store
   295→  store --> ml : cachedModel | null
   296→  deactivate store
   297→end
   298→
   299→alt [Training succeeds]
   300→  ml -> ml : trainAdaptiveModel(candles[], regime)
   301→  ml -> lr : fitLogistic(features, labels)
   302→  activate lr
   303→  lr --> ml : LogisticModel
   304→  deactivate lr
   305→  ml -> ml : predictScore(model, currentFeatures)
   306→  ml --> api : Prediction{up, down}  confidence
   307→else [Training fails — fallback heuristic]
   308→  ml -> ml : heuristicPredict(indicators, regime)
   309→  note right: Fallback: rule-based\nscoring from indicators
   310→  ml --> api : Prediction{up:0.5, down:0.5}  lowConf
   311→end
   312→
   313→deactivate ml
   314→
   315→== AI Text Generation (VDES) ==
   316→
   317→api -> vdes : requestVdesAnalysis(symbol, taResult, regime, prediction)
   318→activate vdes
   319→
   320→vdes -> msl : selectMSLV4(symbol, regime, indicators)
   321→activate msl
   322→
   323→msl -> msl : buildPrompt(taResult, regime, prediction)
   324→msl -> fb : loadFeedbackWeights(symbol)
   325→activate fb
   326→fb --> msl : feedbackWeights
   327→deactivate fb
   328→
   329→msl --> vdes : { prompt, config }
   330→deactivate msl
   331→
   332→vdes -> zai : dedicatedAIChatCompletion(prompt, config)
   333→activate zai
   334→
   335→loop [Retry on 429 / network error — max 3 attempts]
   336→  zai -> zai : attemptChatCompletion(prompt)
   337→  alt [Success — HTTP 200]
   338→    zai --> vdes : AIResponse{content, usage}
   339→  else [Rate Limited — HTTP 429]
   340→    zai -> zai : wait(exponentialBackoff)
   341→    note right: backoff = baseDelay * 2^attempt\njitter ±200ms
   342→  else [Other Error]
   343→    zai --> vdes : AIError
   344→  end
   345→end
   346→
   347→deactivate zai
   348→
   349→opt [AI succeeded]
   350→  vdes -> aip : postProcessAIOutput(rawContent, symbol)
   351→  activate aip
   352→  aip -> aip : validateFarsiContent(content)
   353→  aip -> aip : formatStructuredOutput(content)
   354→  aip --> vdes : ProcessedAIOutput{summary, details, signals}
   355→  deactivate aip
   356→
   357→  vdes -> fb : storeFeedback(symbol, output, userCtx)
   358→  activate fb
   359→  fb --> vdes : stored
   360→  deactivate fb
   361→else [AI failed]
   362→  vdes -> aip : generateFallbackSummary(taResult, regime)
   363→  activate aip
   364→  aip --> vdes : FallbackSummary
   365→  deactivate aip
   366→end
   367→
   368→vdes --> api : VdesResult{aiOutput | fallback}
   369→deactivate vdes
   370→
   371→== Decision Graph Aggregation ==
   372→
   373→api -> dg : evaluateDecisionGraph(taResult, regime, prediction, vdesResult)
   374→activate dg
   375→dg -> bw : getBayesianWeights(symbol)
   376→activate bw
   377→bw --> dg : weights
   378→deactivate bw
   379→dg -> dg : scorePaths(taResult, regime, prediction)
   380→dg --> api : DecisionResult{action, confidence, reasons}
   381→deactivate dg
   382→
   383→== Response Assembly ==
   384→
   385→api -> store : persistAnalysis(symbol, fullResult)
   386→activate store
   387→store --> api : persisted
   388→deactivate store
   389→
   390→api -> store : releaseLock(analysisKey)
   391→activate store
   392→store --> api : released
   393→deactivate store
   394→
   395→api --> page : FullAnalysisResult{ta, regime, ml, vdes, decision}
   396→deactivate api
   397→
   398→page --> User : renderFullDashboard()
   399→deactivate page
   400→
   401→@enduml
   402→```
   403→
   404→**Key Interaction Patterns:**
   405→
   406→| Pattern | UML Construct | Application |
   407→|---|---|---|
   408→| Concurrent data fetching | `par` / `else` | Candlestick + Snapshots fetched simultaneously |
   409→| ML model fallback | `alt` / `else` | `trainAdaptiveModel()` → success, or `heuristicPredict()` → fallback |
   410→| AI rate-limit retry | `loop` + `alt` / `else` | 429 → exponential backoff with jitter |
   411→| Optional caching | `opt` | Cached model lookup before training |
   412→| AI success/failure | `opt` + `alt` | Post-process on success, fallback summary on failure |
   413→| Lock management | `acquireLock` / `releaseLock` | Prevents concurrent analysis for same symbol |

   477→### 12.2 Level 2 — Message Ordering During Regime Detection
   478→
   479→> **سطح دوم:** ترتیب پیام‌ها بین زیرسیستم‌های تشخیص رژیم بازار. این نمودار نحوه ترکیب نتایج فازی، مارکوف، و رأی‌گیری وزنی تطبیقی را با شماره‌گذاری دقیق پیام‌ها نشان می‌دهد.
   480→
   481→```mermaid
   482→sequenceDiagram
   483→    participant api as analysis_api
   484→    participant regime as regime_engine
   485→    participant ta as ta_engine
   486→    participant bw as bayesian_weights
   487→    participant sr as sr_analyzer
   488→    participant vp as volume_profile
   489→
   490→    Note over api,regime: Regime Detection Sub-Interaction
   491→
   492→    api-))regime: 1: detectRegime(candles, indicators)
   493→    regime-))regime: 1.1: fuzzyRegimeDetector(indicators)
   494→    Note right of regime: 1.1a: compute memberships<br/>μ(bullish), μ(bearish), μ(sideways)
   495→
   496→    regime-))regime: 1.2: propagateMarkov(prevState)
   497→    Note right of regime: 1.2a: transition matrix T<br/>1.2b: P(state_t | state_{t-1})
   498→
   499→    regime-))regime: 1.3: adaptiveWeightedVote(fuzzy, markov)
   500→    Note right of regime: 1.3a: λ_fuzzy * fuzzy + λ_markov * markov<br/>1.3b: argmax → regime label
   501→
   502→    regime-))bw: 1.4: computeHistoricalProbabilities(regime)
   503→    bw-))bw: 1.4.1: buildTrendFromDailySnapshots(snapshots)
   504→    bw-))bw: 1.4.2: applyBayesianPriors(probs)
   505→    bw-))regime: 1.4.3: return HistoricalProbs
   506→
   507→    regime-))api: 2: RegimeResult{label, confidence, transition, histProbs}
   508→```

   931→### 14.2 Level 2 — ML Model and Regime State Changes on Specific Events
   932→
   933→> **سطح دوم:** تغییرات وضعیت مدل یادگیری ماشین و رژیم بازار در پاسخ به رویدادهای مشخص. این نمودار چرخه حیات مدل ML (untrained → training → trained → predicting → stale) و وضعیت رژیم (bullish → bearish → sideways) را نشان می‌دهد.
   934→
   935→**ML Model Lifecycle States:**
   936→
   937→| State | Description | Entry Event | Exit Event | Duration |
   938→|---|---|---|---|---|
   939→| `Untrained` | No model available | System startup | `trainAdaptiveModel()` called | Until first analysis |
   940→| `Training` | Model being fitted | `trainAdaptiveModel()` start | Training complete/fails | ≤2s (success) / ≤1s (fail) |
   941→| `Trained` | Model ready for prediction | Training success | `predictScore()` called | Until prediction needed |
   942→| `Predicting` | Computing prediction | `predictScore()` start | Returns `Prediction` | ≤100ms |
   943→| `Cached` | Model stored in safe_storage | `cacheModel()` | Symbol changes / TTL expires | TTL = 5 min |
   944→| `Stale` | Model outdated | TTL exceeded / market shift | `trainAdaptiveModel()` called | Until retraining |
   945→| `Fallback` | Using heuristic | Training failure | Next successful training | Until recovery |
   946→
   947→**ML Model Timeline:**
   948→
   949→```
   950→Event →  Startup   Train     Trained  Predict  Cache   TTL     Stale   Retrain  Trained
   951→        │         │         │        │        │       │       │       │        │
   952→State   │Untained │Training │Trained │Predict │Cached │Cached │Stale  │Training │Trained
   953→        │         │≤2s      │        │≤100ms  │       │5min   │       │≤2s     │
   954→```
   955→
   956→**Regime State Transitions:**
   957→
   958→```
   959→Event →  Open    Indicators  Fuzzy   Markov  Vote    Final   NewDay   Rebuild
   960→        │       │           │       │       │       │       │        │
   961→State   │Unknown│Computing   │Fuzzy  │Markov │Voting │Bullish│Bearish │Sideways
   962→        │       │           │~5ms   │~10ms  │~15ms  │       │        │
   963→```
   964→
   965→| Transition | Trigger | Method | Duration |
   966→|---|---|---|---|
   967→| Unknown → Computing | `detectRegime()` called | — | 0ms (immediate) |
   968→| Computing → Fuzzy | `fuzzyRegimeDetector()` | Indicator membership calc | ~5ms |
   969→| Fuzzy → Markov | `propagateMarkov()` | State transition probabilities | ~10ms |
   970→| Markov → Voting | `adaptiveWeightedVote()` | λ_fuzzy·fuzzy + λ_markov·markov | ~15ms |
   971→| Voting → {Bullish, Bearish, Sideways} | `argmax(voteScores)` | Final regime label | ~2ms |
   972→| Bullish → Bearish | Market regime shift | Daily close + indicators | Next session |
   973→| Bearish → Sideways | Volatility decrease | ATR + ADX threshold | Next session |
